Dicionário de Dados — Modelo Lógico — Trattos

Entrega 2 — Modelo Lógico

Este documento apresenta o dicionário de dados atualizado de acordo com o modelo lógico desenvolvido para a Trattos. Aqui estão descritas as tabelas, atributos, tipos de dados, chaves primárias, chaves estrangeiras e principais restrições previstas para a implementação.

Privacidade: este dicionário não utiliza exemplos contendo dados pessoais reais de clientes, representantes ou responsáveis pela organização. Os dados utilizados posteriormente na massa de testes serão fictícios.
Observação sobre tipos numéricos: no BRModelo Web foi utilizado FLOAT para valores monetários e percentuais porque essa foi a opção disponível utilizada durante a modelagem. No script MySQL, os campos financeiros poderão ser implementados com DECIMAL para maior precisão.
Alterações principais da Entrega 2:
  • valor_comissao foi removido de COMISSAO e será calculado quando necessário;
  • sintomas, medicamentos e alergias foram separados de CONDICAO_SAUDE;
  • formas_pagamento foi separado de FORNECEDOR;
  • os relacionamentos N:N deram origem às tabelas associativas do modelo lógico.

Restrições adicionais previstas para o SQL

  • codigo_representante deverá ser único.
  • numero_pedido deverá ser único.
  • cnpj de fornecedor deverá ser único.
  • mes_referencia deverá aceitar valores de 1 a 12.
  • A combinação id_representante + mes_referencia + ano_referencia deverá ser única.
  • A combinação id_fornecedor + forma_pagamento deverá ser única.
  • Quantidades deverão ser maiores que zero.
  • Valores monetários e percentuais não deverão aceitar valores negativos.
  • data_validade deverá ser posterior a data_fabricacao.
